# 工程评审原文（2026-11-09，全新子 agent，只读）

6 个问题，都是“错误（有明确改法）”。处理见 decisions.md #10。

1. [严重] 实时路径扫描“所有没记过的版本”：回填跳过的无效版本之后永远是“没记过”，改访问码、改分类、删版本都会经过 writeMeta → prepareUpload，要么抛错让这些操作失败，要么用无效时间记成实时更新（违反 R2.3、R1.5）。建议实时路径只看当前版本；扫描全部版本只在启动回填做；加测试“版本无效时改访问码仍成功”。
2. [严重] T3 测试插入位置和“不改现有期望值”矛盾：test-statistics-integration.js:47-74 写死 19 / 21 / 16、弹窗 12+7、结尾 21；按 Q1 A 合计含更新，这些都会变。建议新场景放独立服务实例或新脚本；R1.4 需要的另一个 token、小配额 token 写进 config。
3. [一般] 趋势图分两段会破坏现有交互：statistics.html:287-290 每天一个可聚焦 rect.bar；`.chart rect.selected{fill:#2563eb!important}` 会把两段都染蓝；测试断言 `.bar` 数量为 7。建议每天只保留一个可交互元素，两段只显示，选中用描边或透明度。
4. [一般] 删除前补齐沿用 finalize 的“失败只记警告”会丢更新（statistics-store.js:74-80 吞掉 rename 错误）；按内存判断“已记”会误判。建议补齐用 atomic 直接写正式日志、失败抛错中止删除，以磁盘为准；启动先处理 pending-update 再处理 pending-delete。
5. [一般] `deleted_version_not_recounted` 的场景在真实系统里不会发生（v2 为当前版本时不能删；删了下一个号是 2 不是 3）。建议改为 v1、v2、v3 → 删 v2 → 更新得到 v4。
6. [一般] R1.3 断言放在 test-templates.js 第 171 行之后拿不到管理员 cookie（第 145 行的 cookie 是预览解锁 cookie，管理员登录在第 207 行）。建议挪到第 207 行之后。

评审核对过成立的：所有生成版本的路径都经过 store.writeMeta；版本号 = 最大 + 1，当前版本和第 1 版不能删，prune 保留当前版本；改访问码、改分类读写之间是同步代码，不会和更新交错；更新的 429 只受存储上限限制；更新事件字段不含敏感信息；没有外部影响。
