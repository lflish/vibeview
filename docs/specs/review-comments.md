# 需求评审：页面批注与确认签字

状态：草案。日期：2026-10-22。依赖：[resource-versions.md](./resource-versions.md)、[page-templates.md](./page-templates.md)。

## 目标与范围

开发时会用 dview 出需求和原型预览页，之后需求会反复修改和细化。评审的人有产品、研发和需求提供方（外部的人，没有账号）。

希望形成闭环：**agent 出原型 → 评审的人在页面上批注 → agent 拉取反馈修改 → 更新同一个链接 → 相关角色确认定稿 → agent 按定稿开发**。

只有启用了 `comments` / `signoff` 功能的页面（通常来自 `prd-review` 模板）才有这些能力。普通页面不变。

本版不做：通知（邮件、IM）、@某人、图片和视频上的批注、框选区域批注、每人单独的邀请链接。

## 设计

### 页面结构

- 平台提供外层页面，需求页嵌在沙箱 iframe 里。平时和现在看起来一样，右下角多一个"💬 评论 N"按钮
- 点开后右侧出现评论栏；手机上改为底部弹出
- 顶部显示当前版本和更新说明，可以切换版本
- 评论内容只能在外层输入。只在批注模式下往需求页注入一小段脚本，负责元素高亮，并通过 `postMessage` 告诉外层点了哪个元素。需求页里的脚本拿不到评论接口

### 身份

- 访客凭访问码进入页面。第一次评论时填写姓名和角色（角色来自功能配置里的 `roles`），保存在浏览器
- 这是自报身份，不做校验。页面上明确显示"署名由评论人自行填写"
- 拥有该资源的账户（agent）通过 token 评论，显示为"agent"

### 批注

- 批注模式下，鼠标移到元素上会高亮，点击后打一个编号标记并填写评论
- 也可以写不对应元素的整页评论
- 每条批注保存：子页面路径、版本号、元素选择器、元素里的一段文字、元素内的相对位置、视口宽度
- 发新版后，按选择器和文字重新定位；找不到就标"可能已过时"，并显示为整页评论
- 点右侧评论会定位到对应元素；点页面上的编号会跳到对应评论

### 评论状态

```
待处理 → 已修改（等确认） → 已关闭
              ↘ 打回 → 待处理
```

- 任何人都可以回复
- agent 只能把评论标成"已修改"，并附上修改说明和版本号
- 只有提出人（同一个浏览器署名）或资源所属账户可以关闭或打回
- 决策人（`signoff.decider`）可以把几条评论标为"有冲突"，并给出结论

### 确认签字

- `signoff.required` 里的每个角色至少有一人点"确认当前版本"后，这个版本锁定为**定稿版本**
- 还有未处理的评论时，确认按钮旁边给出提示，但不阻止确认
- 定稿后再更新页面，会生成新版本，状态回到"评审中"，需要重新确认；定稿版本保留，不被版本上限清理
- 页面状态：草稿 → 评审中 → 已定稿

### 数据

评论存在 SQLite（与资源索引同库，新表 `comments`、`signoffs`），按资源 ID 关联。删除资源时一起删除。

### 接口

访客（凭访问码）：

- `GET /v/<id>/_review/comments`
- `POST /v/<id>/_review/comments`
- `POST /v/<id>/_review/comments/:cid/replies`
- `POST /v/<id>/_review/comments/:cid/state`（关闭、打回）
- `POST /v/<id>/_review/signoff`

账户（token）：

- `GET /api/me/items/:id/comments?state=open`
- `POST /api/me/items/:id/comments/:cid/replies`
- `POST /api/me/items/:id/comments/:cid/state`（标为已修改）
- `GET /api/me/items/:id/review`（页面状态、签字情况）

接口按 IP 和访问码限流，评论长度上限 4000 字。

### CLI 与 agent 流程

```bash
dview comments <id> --open --json      # 未处理评论，带角色、版本、位置、元素文字
dview reply <id> <cid> "已改为手机号和用户名都可以登录"
dview mark-done <id> <cid> -m "v4 已修改"
dview review <id>                      # 页面状态、谁确认了、谁还没确认
```

`prd-review` 模板的 guide 告诉 agent：

1. 修改需求前先拉未处理评论
2. 一次修改处理一批评论，更新同一个链接，`-m` 写明处理了哪些
3. 逐条标为"已修改"，不要关闭评论
4. 遇到相互冲突的意见，不要自己决定，回复说明冲突，等决策人处理
5. 开发时以定稿版本为准；还没定稿就开发时，先提醒用户

### 管理端

- 资源列表显示评审状态和未处理评论数，可以按评审状态筛选
- 资源详情显示评论和签字记录；管理员可以删除评论

## 验收

- [ ] 没有启用评论功能的页面，外观和行为与现在一致
- [ ] 外部访客凭访问码可以评论，不能调用账户接口
- [ ] 需求页里的脚本无法读取或提交评论
- [ ] 发新版后，元素还在的批注能正确定位，元素不在的批注标为"可能已过时"
- [ ] agent 只能标"已修改"，不能关闭评论
- [ ] 所有必需角色都确认后，版本锁定为定稿；之后再更新，状态回到评审中
- [ ] `dview comments --open --json` 的输出足够 agent 定位要改的地方
- [ ] 手机上可以查看和发表评论

## 待定问题
