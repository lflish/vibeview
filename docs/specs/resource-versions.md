# 资源版本化

状态：已实现，随 v1.4.0 发布。日期：2026-10-22。

## 目标与范围

现在每次上传都会生成新的 ID。需求页改 5 轮，就会出现 5 个链接、5 个访问码，发出去的旧链接看不到最新内容。

本版让同一个资源可以多次更新：

- 链接固定：`/v/<id>` 始终显示最新版本
- 每次更新保存一个版本，可以查看历史版本
- 访问码、分类、标签在更新时保持不变
- 项目里用 `.dview.json` 记住"本地文件 → 资源 ID"，agent 上传时自动更新，而不是新建

本版不做：版本对比视图（放到 review-comments）、版本数量配额以外的清理策略、跨账户更新、统计页单独统计"更新"次数。

## 设计

### 存储

```
data/<type>/<id>/<filename>                  # 第 1 版：位置和以前一样，旧数据不迁移
data/<type>/<id>/.versions/2/<filename>      # 第 2 版起
meta/<id>.json                               # 增加 versions 数组、current、updatedAt
```

`.` 开头的路径不会被站点解压写入，也不会被预览路由读出，所以 `.versions/` 对外不可见。删除资源时整个 `<id>/` 目录一起删除。

上传时文件先照常落在一个临时 id 的目录里，确认归属和类型后整体改名到 `.versions/<n>/`，再写元数据。同一资源的更新在进程内串行执行，版本号不会冲突。

`meta` 新增字段：

```json
{
  "current": 2,
  "versions": [
    { "n": 1, "filename": "prd.html", "size": 12034, "createdAt": "...", "message": "", "git": null },
    { "n": 2, "filename": "prd.html", "size": 13501, "createdAt": "...", "message": "补充错误提示", "git": { "commit": "eb84159", "dirty": false } }
  ]
}
```

- meta 顶层的 `filename`、`mime`、`fileCount`、`archiveName` 始终是当前版本的；`size` 是所有保留版本的总和
- 旧资源没有 `versions` 字段，读取时当作只有一个版本，文件位置不变，不做强制迁移
- 资源类型在不同版本之间不能变（html 不能更新成图片），站点和单文件 HTML 也不能互换
- 一个资源最多保留的版本数由配置 `versions.max_per_resource` 决定（默认 50，最小 2），超出时删除最早的版本；第 1 版、当前版本和标记了 `locked` 的版本（给以后的确认签字用）不删
- 资源占用的配额 = 所有版本的大小之和

### 预览路由

| 路径 | 内容 |
| --- | --- |
| `/v/<id>` | 当前版本 |
| `/v/<id>/@<n>` | 第 n 个版本（单文件），原文件为 `/v/<id>/@<n>/raw` |
| `/v/<id>/@<n>/...` | 第 n 个版本（站点）；`/v/<id>/@<n>` 跳转到带斜杠的地址 |

访问码对所有版本都有效。访问码过期只影响访问，不删除版本。打开受保护的历史版本时先显示访问码表单，验证后回到该版本。受保护站点的历史版本地址是 `/v/<id>/~<凭证>/@<n>/...`。

站点的顶层目录不能命名为 `@<数字>`，上传时拒绝。

### 接口

- `POST /upload` 增加可选字段 `id`：带上时表示更新这个资源，只能更新自己账户的资源；增加可选字段 `message`、`git_commit`、`git_dirty`
- `GET /api/me/items/:id/versions`：版本列表
- `DELETE /api/me/items/:id/versions/:n`：删除某个版本（不能删当前版本和第 1 版）
- 管理端同样提供这几个接口

返回值在原来的基础上增加 `version`（这次上传后的版本号）和 `updated: true/false`；更新时还返回 `versionUrl`（这一版的永久地址），不返回新访问码。

更新时：访问码不变；分类字段只覆盖请求里出现的；`description` 原本取自页面标题时跟随新版本，手动设置的保持不变。配额检查不增加文件数，存储按新版本大小累加。

### CLI

```bash
dview upload prd.html                     # 有 .dview.json 映射就更新，否则新建
dview upload prd.html -m "补充错误提示"     # 带更新说明
dview upload prd.html --new               # 强制新建
dview upload prd.html --id a8f3k2         # 指定更新某个资源
dview versions a8f3k2                     # 版本列表
```

`.dview.json` 放在 git 仓库根目录，提交进仓库：

```json
{
  "items": {
    "docs/prd/login.html": "a8f3k2",
    "docs/prototype/": "x9d1m7"
  }
}
```

- 路径相对于仓库根目录
- 新建资源后，CLI 自动写入映射
- 映射的资源已经被删除或不属于当前账户时，提示用户，不自动新建
- 仓库外的文件、被 `.gitignore` 忽略的文件不写映射；`--no-map` 不读写映射；`--id` 更新后也会写入映射
- 在 git 仓库里上传时，自动带上当前 commit；被上传的文件有未提交改动时 `dirty: true`
- Skill 自带的 `upload.sh` 不读映射，只支持 `--id` 和 `-m`

### 管理端

资源名旁边显示版本号（只有一个版本时不显示），点击或通过「⋯ → 版本历史」打开版本列表：版本号、时间、大小、说明、commit，可以打开任意版本、删除历史版本（点两次确认）。

### 过期清理

`storage.retention_days` 从最后一次更新（`updatedAt`）算起，没有更新过的从创建时间算起。

## 待定问题

实现时按下面的默认处理，需要调整时再改：

1. 单个资源默认保留 50 个版本：可通过 `versions.max_per_resource` 调整。
2. 更新时访问码有效期**不顺延**：有效期是分享方对访客的承诺，更新内容不应悄悄延长。需要延长时在管理端或用 `PATCH /api/me/items/:id/access` 修改。
3. 统计页**暂不区分**新建和更新：现有统计日志按资源 id 记一条上传事件，记录每次更新需要改日志结构，放到以后需要时再做。更新后当前存量的体积会跟着变化。

## 变更记录

- 2026-10-22：历史版本地址由 `/v/<id>@<n>` 改为 `/v/<id>/@<n>`。访问码验证后的 cookie 作用路径是 `/v/<id>`，浏览器不会把它带到 `/v/<id>@<n>`，按原写法受保护的历史版本无法打开。
- 2026-10-22：存储布局改为第 1 版留在原位、后续版本放在 `.versions/<n>/`，旧数据不用迁移。
- 2026-10-22：统计里单独记录"更新"移出本版。
- 2026-10-22：过期清理改为从最后一次更新算起。
