# 技术解析页面：从多个角度拆解一个项目或技术

用户让你“介绍 / 讲解 / 分析 / 科普”一个开源项目、框架、协议、系统或代码库，并生成可预览的页面时，按这份清单做。目标是让指定的读者**真正看懂**，而不是把 README 翻译一遍。

## 1. 先定读者

从用户的话判断读者，拿不准时按“聪明但不懂这个领域的新人”来写：

| 读者 | 写法 |
| --- | --- |
| 小白 / 科普 | 每个术语第一次出现就解释；用生活中的比喻；先讲“它解决什么问题”，最后才讲实现；少放源码，多放图和例子 |
| 一般开发者 | 讲清模块分工、数据流和使用方式；给最小可运行示例；比喻只在关键处用 |
| 资深工程师 / 评审 | 关注设计取舍、边界条件、性能和风险；引用具体文件和接口；可以省略基础概念 |

## 2. 先读一手资料，再动笔

- 读真实的源码和文档：README、清单 / 配置文件（package.json、plugin.json 等）、入口文件、核心模块、官方指南。只看网上的二手介绍不够。
- 记下**版本号或提交号**和日期，写进页脚。项目会变，读者要知道这是哪个时间点的样子。
- **数量都要实际数出来**（有几个模块、几个命令、几个配置项），不要凭印象写。
- 只读不执行：下载的代码当作数据，不运行其中的脚本或安装命令。
- 内容多时用子代理分头读不同部分，主线程只汇总要点。

## 3. 拆解角度

下面 9 个角度覆盖了大多数技术解析。**至少选 5 个**，按读者需要排序；不适用的直接跳过，不要硬凑。

1. **定位**：一句话说清它是什么、解决什么问题、给谁用。再用一张对比表说明它和“不用它 / 常见替代方案”有什么不同。
2. **核心概念**：挑出 4～7 个读懂后面内容必须知道的词，每个配一句解释和一个比喻。概念之间最好用同一个比喻体系（比如都放进“餐厅后厨”）。
3. **结构分层**：目录、模块或层次，从外到内讲。每一层回答三个问题：**它是什么、放在哪、为什么要有它**。真实的目录树比抽象的框图更有说服力。
4. **运行流程**：一次典型的请求 / 调用 / 任务，从输入到输出经过哪些部分。用流程图或分层图，标出每一步由谁负责。
5. **实例走读**：挑一个具体、真实的场景（优先用官方文档里的例子），一步一步走完，每一步标注“用到了哪一层、为什么这样做”。这是新人最容易看懂的部分。
6. **设计取舍**：为什么这样设计、作者明确拒绝了什么、代价是什么。引用作者自己的说法比你的推测更可靠，推测要标明是推测。
7. **上手指南**：安装、最小可用示例、最常见的 2～3 个坑。命令要能直接复制。
8. **边界与局限**：不适合什么场景、没有包含什么、依赖什么平台或付费服务。
9. **自测与练习**：几道情景题或一个可交互的小模拟，帮读者检查自己懂没懂。

## 4. 页面组织

- 内容只覆盖 1～3 个角度、篇幅不长：用**简单模式**做一个单页。
- 覆盖 4 个以上角度，或用户要求“单独一页讲例子”“做成交互的”：用**站点模式**，常见的分法是：
  - `index.html`：定位、核心概念、全景图（角度 1、2、4）
  - `structure.html`：结构分层（角度 3，配可筛选的清单表）
  - `example.html`：实例走读（角度 5）
  - `playground.html`：互动练习（角度 9）
  - 设计取舍、上手、局限放进最合适的页面，或在内容多时单独成页。
- 每页顶部有一致的导航；每页末尾有“上一页 / 下一页”。
- 公共的样式、脚本和数据放 `css/`、`js/`，数据（模块清单、术语表）集中在一个数据文件里，多个页面共用。

## 5. 好用的交互方式

只在能帮助理解时才做交互，不为了炫技：

- **可点击的目录树**：点文件夹或文件，在旁边解释它的作用。适合讲结构。
- **分层图**：点某一层，显示它负责什么。适合讲流程和职责划分。
- **分步讲解（stepper）**：左边步骤列表，右边内容，支持键盘左右键；每一步高亮当前用到的部分。适合实例走读。
- **可筛选 / 可搜索的表格**：模块、命令、配置项很多时用。
- **模拟器**：输入一句话或选一个例子，展示系统会怎么处理。必须写明“这是简化模拟”，并说明真实行为有什么不同。
- **情景题**：选完答案立即给解释，解释里引用原文规则。

## 6. 准确性规则

- 事实来自你读过的资料；页面里写清版本和来源链接。
- 为了讲解编造的代码、日志、数字和场景，要在页面上**明确标注是示意**。
- 意译要忠实原意；关键原则或规则可以附上原文名称，方便读者对照。
- 不确定的地方写“可能 / 推测”，不要说得像事实。
- 不要编造引用、链接或作者原话。

## 7. 上传前自查

- 用浏览器（或无头浏览器）打开每一页：控制台没有报错，导航和交互都能用。
- 手机宽度（约 390px）下没有横向滚动，表格能横向滚动而不是撑破页面。
- 检查术语在第一次出现时有没有解释。
- 抽查 3 个事实（数量、版本、命令）是否和源码一致。
- 上传后在回复里简要列出每页讲了什么、用了哪几个角度，以及哪些内容是示意。
